# Pigeon — closeout, 2026-07-31

The day pigeon went from "committed" to "used". Six PRs, all of them driven by
running the thing against real keys rather than reading the code.

## How the day actually went

The founder reported it "still does not work". It did not, for reasons nobody
had guessed:

- `coo check` printed a correct report and then **exited 1** — the trailing
  `[[ $dead -gt 0 ]] &&` was the last command, so a healthy nest returned failure.
- Choosing "check" on an empty nest **killed the whole tool**: `die` calls `exit`,
  so `cmd_check || true` could not protect it.
- `coo doctor` **printed a live API key in plaintext**. zsh echoes `name=value`
  when `local` re-declares a name already in scope, and `local stored` sat inside
  a loop. For a tool whose promise is "values are never printed", that was the
  worst bug in the repo.

Fixing those exposed the real problem: the input was the product, and the input
was a hardcoded nine-provider menu that ended by telling you to run another
command with placeholder arguments. That became v0.2.

## Twice it broke a real project

Both times the fix was a rule the code did not yet have. Both times a backup
saved it. Recording them because they are the reason v0.3 is a trust slice and
not a feature slice.

**1. Per-project keys treated as stale copies.** Rotating taste-machine's
Supabase key wrote it over litmus's own Supabase key, in litmus's `.env`, twice
in one run. `scan` already knew only openrouter/anthropic/openai/github are
account-scoped; the landing code did not. It does now, from one shared list, and
anything absent is never bulk-written.

Worse, the same run wrote a *secret* into `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
— a variable that ships to browsers. And because two declared vars lived in one
file, the second write backed up the file the first had already modified, so one
original was unrecoverable.

**2. A test run against the real machine.** An automated keystroke test aimed at
the real `$HOME` instead of the sandbox, stored a one-character value and fanned
it. Restored from backups. The lesson stuck: every destructive path after that
was tested against a fake `$HOME` or a stub binary on `PATH`.

## Things that only appear when a human uses it

- Copying a key out of a terminal brings the shell prompt with it. `❯sk-ant-…`
  is not `sk-ant-…`, and **macOS `security -w` hex-encodes any value containing
  non-ASCII** — so the Keychain handed back different bytes than went in, and
  pigeon wrote a value into two `.env` files that nobody had ever pasted.
  `kc_set` now verifies the round trip and refuses on mismatch.
- Every HTTP probe treated a failed `curl` exactly like a 401. A dropped
  connection would report a live key as DEAD — and the natural response to DEAD
  is to go revoke it.
- `--redeploy` on `rotate` silently did nothing: `land_it` calls `cmd_fan`
  internally with no arguments, so a function-local flag could never survive.
- Vercel CLI ≥55 enables `--non-interactive` by itself "when an agent is
  detected" and then **ignores piped stdin** — `printf %s "$key" | vercel env add`
  exited 0 and stored an empty string. And `npx vercel` resolves whatever node is
  first on PATH, which on this machine was node 16 in a login shell and node 22
  otherwise. That read as flakiness for hours until the code stopped discarding
  stderr.

## Verified today, against reality

- Two real keys landed end to end: an Anthropic key (live-probed before storing,
  fanned to two projects) and a Supabase secret (landed in `.env.local`, pushed
  to Vercel production, deployed).
- Litmus proven untouched by the Supabase rotation, in a two-project sandbox and
  again on the real machine.
- Terminal restored after `SIGTERM` mid-picker.
- `--redeploy` fires only with the flag, proven against a stub CLI on `PATH`.
- gitleaks: no leaks found.

## Known-open

- **The 60 provider prefixes were written from memory, not vendor docs.** A wrong
  one causes a false "wrong provider" block, in the guard everything leans on.
- **No probe for `sb_secret_`.** Today's Supabase key was stored and deployed
  with nothing verifying it is the right key.
- **Nobody but the author has ever run it.** The repo is private, so the README's
  `git clone` does not work for anyone else.
- macOS only. `security` and `pbpaste` are load-bearing.

## One-line state

pigeon is a single ~1,200-line zsh file that a human used to rotate two real keys
into production today. The reading verbs are solid; the writing verbs have been
correct for about an hour, and v0.3 is about earning trust in them rather than
adding to them.
